# M9 第二批：首次启动向导与可卸载性（分发准备）

2026-08-21 与用户 brainstorming 定稿。

## 这一批要解决的问题

用户原话：

> 比方说我让别人去使用，比方说给我太太使用，她可能只会装一个 App。那么这个
> App 点击第一次使用的时候，应该有一系列的设置向导，包括这个 App 对应的主要的
> 文件夹，未来用来下载各种模型存放以及其他等等的设置可以落盘的东西。

**验收标准因此不是「加了几个设置项」，而是：一个只会双击安装包的人，装完能
自己说出第一句话。** 目前做不到——原因不是缺少界面，是两个硬缺口：

1. **模型路径是开发者专用的。** `ModelCatalog.defaultRoot(appBundleURL:)` 从
   `.app` 往上数两级去找 `vendor/models`，因为它假定 app 躺在 `<仓库>/dist/`。
   装进 `/Applications` 就变成找 `/vendor/models`，必然落空。代码注释里写着
   「正式分发时应改为应用支持目录（M6 范围）」——推迟至今。
2. **没有任何首次启动引导。** 麦克风与辅助功能两项权限、模型从哪来，全靠
   使用者自己知道。

## 已拍板的决策（全部经用户逐项确认）

| 决策点 | 结论 | 落选项与理由 |
|---|---|---|
| 范围 | **只保主链：说话 → 出字** | 「校正/翻译也自动化」——需自己写 2GB 级下载器，周期明显变长；「先只做设置界面」——本批结束时太太仍然装不起来 |
| 存储位置 | **固定 `~/Library/Application Support/vInput/`，不问用户** | 「向导里让用户选」——非技术用户多一道看不懂的选择，且选到文稿/桌面/iCloud 会**挂死**（见下方证据）；「默认固定但设置可改」——迁移、回退、路径失效都要额外做，本批不值 |
| 转写模型 | **只用 turbo，不给选择** | 用户 2026-08-21：「目前我用下来觉得 Turbo 模型就够用」。向导里因此没有模型选择步骤 |
| 下载源 | **官方与国内镜像并发探测，谁先响应用谁** | 「只用官方 + 失败给退路」——用户现在在国内，等于第一次启动就断；「只用镜像」——9 月到西班牙后反而更慢 |
| 权限引导 | **只引导麦克风与辅助功能** | 「四项全引导」——只用内置麦的人被迫开两个用不上的开关，而那两个名字听起来很吓人；遥控器/鼠标要用的蓝牙与输入监控，等真去连设备时再引导 |
| 设置界面 | **不做独立窗口**（进阶项收进面板「高级」折叠区） | 独立窗口会让同一个选项有两个入口、迟早分叉——本仓库在 `attachTranslation` 上栽过同一个坑 |
| 卸载 | **面板里给「卸载」** | 用户 2026-08-21 追加：「你装到了一个用户不感知的目录下，又下载了几个 G 的文件在该目录当中，所以必须让用户感知这个东西是可以卸载」 |

## 支撑决策的实测证据

**模型体积**（本机 `du -sh`）：turbo 1.5G、large-v3 2.9G、base 140M；
校正/翻译用的 qwen3-4b 2.1G、qwen2.5-7b 4.0G。「首次下载」是分钟级的事件，
不是一闪而过——所以要进度、要能和权限步骤并行。

**为什么不让用户自选目录**（`WhisperKitTranscriber.swift:288-292` 的注释，
真机实测记录）：本应用是 LSUIElement（纯菜单栏、无主窗口），访问受保护目录
触发的授权弹窗**无处呈现**，`open()` 会无限期阻塞——实测卡住 5 分钟仍未返回，
堆栈停在 `HubApi.configuration(fileURL:)` 的 `open()` 上。换到应用支持目录后
不受 TCC 约束。**用户随手选到文稿/桌面/下载/iCloud Drive，应用就是挂死而不是
报错**，这个失败形态对非技术用户是灾难性的。

**下载能力是现成的，不用改 `vendor/`**：
`WhisperKit.download(variant:downloadBase:useBackgroundSession:from:token:endpoint:progressCallback:)`
是 public，同时给了三样正需要的东西——`endpoint`（可传镜像）、
`progressCallback`（向导进度条不用自己造）、`downloadBase`（已指向应用支持
目录）。底层 `HubApi` 也支持自定义 endpoint（默认 `https://huggingface.co`）。
**这一条是「只保主链」这个范围决定的技术基础**：转写模型的获取几乎免费，
而校正/翻译的 MLX 模型没有等价能力，自己写才是真成本。

## ① 存储位置规范化

全部收进 `~/Library/Application Support/vInput/`：模型在 `huggingface/`
（WhisperKit 已经在用这个位置，不动它），向导状态与偏好在旁边。

**查找顺序：① `vendor/models`（存在才用）→ ② 应用支持目录。**

第一条是给开发机留的：本机 `vendor/models` 里有 4.5GB 模型，重下不现实。
分发版那台机器上它不存在，于是永远走第二条；开发机照旧走第一条。
（顺序以 `ModelCatalog.resolveRoot` 为准——本文原先把两条写反了，
`ModelRootResolutionTests.developmentPrefersVendorModels` 钉的是代码这一份。）
**两边都活，且不需要环境变量或构建配置来区分**——判据就是「那个目录在不在」。

面板的「高级」区给一个「在访达中显示」，让好奇的人能看见东西放在哪。

## ② 首次启动向导

LSUIElement 应用没有主窗口，向导需要自己开一个真窗口
（`BenchRecordingWindowController` 是现成先例，含 `.titled` 窗口的创建与
生命周期）。

五步：**欢迎 → 麦克风 → 辅助功能 → 下载模型 → 试说一句。**

三个关键设计：

- **下载与授权并行。** 进入向导就在后台开始下 turbo，用户同时去授权。1.5GB
  的等待被权限步骤吃掉，而不是干等。到「下载模型」这一步时通常已经完成或
  接近完成。
- **辅助功能无法用弹窗授予**，必须用户去系统设置手动打开。因此那一步给
  「打开系统设置」按钮（直接跳到对应面板）+ 轮询检测，**授权成功自动前进**。
  不做自动检测的话，用户不知道自己算不算做完了——这是这类向导最常见的卡点。
- **可中断可续。** 向导状态落盘（走完了哪几步）。中途关掉窗口，下次启动
  接着走，不从头再来，也不把已经完成的权限再问一遍。

「试说一句」这一步是**验收而不是装饰**：它让用户在向导内部就确认整条链
（麦克风 → 转写 → 注入）通了，而不是关掉向导之后自己去试、失败了也不知道
问题在哪。这一步注入到向导窗口自己的文本框里，不碰别的应用。

## ③ 下载源：并发探测

同时向官方与镜像各发一个轻量探测请求，**谁先响应就用谁**下载；两个都不通
时报清楚发生了什么，并给「我已经有模型文件」的手动导入入口（用户可以把本机
现成的模型目录拷给太太）。

这样国内国外都不必问用户任何问题，用户 9 月到西班牙后也不用改设置。
面板「高级」区留一个可强制指定下载源的开关兜底。

**已知风险**：镜像内容与官方是否逐字节一致，不由我们控制。缓解是下载完成后
校验（WhisperKit 自己会做文件完整性检查），以及记日志写明这次用的是哪个源
——出问题时第一时间能分清是模型坏了还是源坏了。

## ④ 卸载

入口在面板「高级」区。二次确认时**说清楚要删什么、多大**（实际扫盘算出体积，
不写死数字）。删除范围：

| 项 | 路径 |
|---|---|
| 模型与缓存 | `~/Library/Application Support/vInput/` |
| 日志 | `~/Library/Logs/vInput/` |
| 偏好设置 | `com.vinput.app` 的 UserDefaults |
| 云端 API key | Keychain 条目 |

删完提示两件**我们做不到**的事，不许假装做到了：把 App 拖进废纸篓（应用删不掉
自己），以及系统设置里可以移除「辅助功能 / 麦克风」的授权条目。然后退出应用。

## ⑤ 设置界面：不做独立窗口

原 M9 计划里的「设置界面」在本批**主动放弃**。面板已经承担了全部设置，
再开一个窗口只会让同一个选项有两个入口、两处文案迟早分叉。进阶项
（校正模型目录、云端 API key、储存位置、下载源、卸载）收进面板的「高级」
折叠区——面板已经是手风琴结构，多一行不增加复杂度。

## 不做什么

- 校正 / 翻译模型的自动下载（MLX 那 2GB，进阶项，用户仍手动选目录或用云端）。
- 让用户自选储存位置（决策表已述理由）。
- 独立设置窗口。
- 自动更新、崩溃上报、公证与分发渠道——那是再下一批的事，本批只保证
  「拿到 .app 的人能用起来」。
- 遥控器/鼠标相关权限的向导引导（等实际连接设备时再说）。

## 风险

**最大的一条：向导的每一步在测试进程里都跑不起来**——真窗口、真 TCC 授权、
真网络下载。因此设计上把可测的部分尽量榨出来（见下），剩下的靠真机验收，
并且**如实标注哪些只有真机能证明**，不假装测过。

次一条：并发探测选源在网络抖动时可能选到较慢的那个源。代价有界（下得慢，
不是下不到），且日志写明用了哪个源，事后可查。

## 测试与验收

- **纯函数化**：向导的步骤推进与状态恢复、权限检测结果 → 下一步的映射、
  卸载清单（要删哪些路径、体积怎么算）、下载源选择策略，全部做成
  `nonisolated static` 纯函数或可注入的类型，单测覆盖。
- **协议隔离**：网络探测、下载、TCC 查询、文件删除各抽协议，测试用假实现。
  **删除动作尤其要隔离**——测试里绝不能真的去删家目录里的东西。
- **每条测试做变异验证**（仓库强制规矩），交变异表。
- 完工后 `./scripts/test.sh` + `./scripts/build-app.sh` 全绿，派专门 QA 代理
  查跨任务接缝，修完再请用户真机验收。
- **真机验收要在一台没有 `vendor/models` 的干净环境里做**——否则回退路径会
  掩盖掉「分发版找不到模型」这个本批要修的核心缺口。可行做法：临时改名
  `vendor/models`，或在另一个账户/机器上装。
