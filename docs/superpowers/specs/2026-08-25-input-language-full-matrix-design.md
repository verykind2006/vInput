# 输入语言可选 + 翻译全矩阵（2026-08-25）

## 问题

用户实说英文时，识别结果被当成中文处理——转写语言在
`AppModel.makeTranscriber` 里写死 `language: "zh"`，且整条管线（标点
prompt、繁→简、拼音校正、中文数词改写、翻译 prompt、质量闸门）都以
「源恒为中文」为前提。用户要能在面板里指定「我说的是什么语言」。

## 决定过程（三个方向都议过）

1. **只加英文**（输入 = 中/英两档）——落选，用户拍板要全量。
2. **Whisper 自动检测**——机制上可行（vendor 里 `detectLanguage` 接口
   现成，turbo 保留检测头），但检测是**整段判一种语言**：中英混杂、
   术语密度高的句子可能被判成英文，而按英文解码时中文部分整个变形
   （音译或被翻译）。现在的主路径「中文夹英文术语」好用，恰恰因为钉死
   了 zh。用户权衡后放弃检测，选手动指定。
3. **手动指定，全矩阵**（本设计）：输入七档（中/英/西/德/葡/法/意），
   目标 =「不翻译 | 翻译成任一语种」，含新增的 X→中文方向。

## 核心概念：一个语言枚举，两处使用

- `TranslationTarget` 更名 **`Language`**，七种，rawValue（语言码）与
  displayName / englishName / usesLatinScript 原样保留，全应用共享。
  落选项：另造 `InputLanguage` 枚举——七种语言写两遍必然漂移，
  M8 的 `usesLatinScript` 别名教训就是这么来的。
- **输入语言**：新增偏好，默认中文，持久化，重启保持。
- **翻译目标**：两态——「不翻译」（独立档位，不再借用「中文」表示）
  或「翻译成某语种」。**目标 == 输入时等同不翻译**：不建管线、不烧模型。
- 所有按语言分流的地方用**无 `default` 的穷尽 switch**：加第八种语言时
  漏配是编译错误，不是静默错。

### 偏好迁移（一次性）

老用户存的目标 `"zh"` 当时含义是「不翻译」。首次启动读到旧值时映射为
新「不翻译」档并记日志。新的「翻译成中文」用新存储值，与旧值不冲突。
迁移不可逆但无损：旧语义只有这一个歧义点。

## 数据流

```
面板(输入语言) → AppModel → 转写器 language=设置值
                   │           ├ 标点 prompt：仅输入=中文（其余语种裸解码，未实测，见「不装作验过」）
                   │           └ 繁→简：仅输入=中文
                   ├→ 校正：仅输入=中文时挂载（拼音同音字机制对拉丁文无意义），
                   │        否则不挂载并记日志
                   └→ 翻译协调器：携带 (输入, 目标) 二元组
                        ├ 中文数词→阿拉伯数字改写：仅输入=中文
                        ├ prompt："Translate the following {输入.englishName}
                        │          text into {目标.englishName}."
                        └ 闸门：按目标书写系统分流（下节）
```

**转写器重建**：输入语言改变时走模型切换已有的重建路径（`language` 是
构造参数），不新造机制。切换后无需重启 app 即生效。

## 闸门矩阵

| 目标 | 判据 |
|---|---|
| 拉丁语种 | 现有四条原样沿用：残留汉字、中文标点、没说完、太短。「残留汉字」对**任何**输入都成立——英译西的译文里同样不该冒出汉字 |
| 中文（新方向） | 「译文须含至少一个汉字」+ 没说完 + 太短。**不查**拉丁残留：中文里合法保留英文术语正是本项目自己的规则。此闸门弱且未实测，如实标注 |
| 不翻译 / 目标==输入 | 不进管线，无闸门 |

回退文案「已退回中文原文」→「已退回原文」（四种成因文案同步改）。

## 面板 UI

- 新增「输入语言」子菜单，七档，当前档打勾，默认中文。
- 翻译目标菜单第一项改为「不翻译」；「中文」降为普通一档。
- **质量分级只在输入=中文时显示**——那是 zh→X 的实测数字；输入非中文时
  各目标标「未实测」，不虚标。
- 输入非中文时「校正」菜单置灰并注明「仅中文输入可用」——比静默跳过诚实。

## 不装作验过（写进 Roadmap 未验证清单）

- 除 zh→六种外的所有 (输入, 目标) 翻译组合的质量。
- 六种拉丁语种裸 prompt（无标点引导）下的标点表现。
- X→中文方向的「须含汉字」闸门的实际拦截/误拦率。
- `TranslationBudget` 的按字符数缩放是拿中文字符实测标定的，拉丁文本
  字符数天然多约数倍，超时预算会偏大（有 30 秒 ceiling 兜底）——
  行为安全但数字未标定。

## 测试

- **单测**：prompt 生成矩阵（对角线 + 代表组合）；闸门分流穷尽；偏好迁移
  （旧 `"zh"` → 不翻译）；转写器构造参数接线——「值对了」和「接上了」
  分开验（输入语言真的传进了 `language:`）；非中文输入时校正确实未挂载；
  目标==输入时管线确实没建。每条按本仓惯例（见 docs/Roadmap.md「变异验证」）
  做变异验证并交变异表。
- **真机清单**：实说英文出英文文字；英文→西文一轮；切输入语言不重启
  生效；**中英混杂在输入=中文下不劣化**（主路径回归）；切语言期间说话
  的行为与换模型期间一致。

## 明确不做

- 自动语言检测（议过，落选，理由见「决定过程」）。
- 日语/韩语（`Language` 注释里的原理由依旧成立：无判断质量的手段）。
- 非中文输入的校正（机制是拼音的，不是「以后补」而是「不适用」）。
- 逐句混说多语种（Whisper 单窗单语言，超出本工具形态）。
