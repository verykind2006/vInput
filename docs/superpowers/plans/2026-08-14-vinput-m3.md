# vInput M3 实施计划：蓝牙遥控器接入

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按住小米遥控器的语音键说话，效果与按 `⌥D` 完全一致——HUD 出现、实时预览、松手转写、注入光标。

**Architecture:** 新增 `AudioSourceRouter` 在内置麦与蓝牙源之间路由，`DictationSession` 一行不改。移植上游的 BLE 协议层（ATVV + IMA ADPCM + CoreBluetooth 状态机），其 delegate 回调 `didStartVoice` / `didStopVoice` / `didDecode` 正好对应会话的 `start` / `finish` / 音频帧。返回键取消走自写的最小 HID 监听。

**Tech Stack:** CoreBluetooth（BLE）、IOKit.hid（返回键）、移植自 [HD838A/remote-mic-app](https://github.com/HD838A/remote-mic-app)（GPL-3.0-only）。

### 7. HID 侧的硬事实

- 设备匹配：VendorID `0x2717`、ProductID `0x32B8`
- 返回键 usage `0xF1`（**不是**标准 Escape `0x29`）
- 报文解析（上游 `RemoteButtons.swift:600-616`，仅 17 行）：

```swift
static func usages(reportID: UInt32, data: Data) -> Set<UInt16>? {
    guard reportID == 1 else { return nil }
    var bytes = Array(data)
    if bytes.count == 7, bytes.first == UInt8(reportID) {
        bytes.removeFirst()
    }
    guard !bytes.isEmpty, bytes.count.isMultiple(of: 2) else { return nil }

    var result = Set<UInt16>()
    for index in stride(from: 0, to: bytes.count, by: 2) {
        let usage = UInt16(bytes[index]) | UInt16(bytes[index + 1]) << 8
        if usage != 0 { result.insert(usage) }
    }
    return result
}
```

### 8. 测试写法的既有约定

- 用 Swift Testing（`@Suite`、`@Test`、`#expect`），不是 XCTest
- 测试命令一律 `./scripts/test.sh`，不要用 `swift test`（纯 CLT 环境会报 `no such module 'Testing'`）
- **不要在 `#expect` 里把 `CGFloat` 与内联算术表达式直接比较**——宏展开时右侧会被单独推断成 Int，`750.0 == 750` 会误判为失败。先算进有类型的常量再比较
- 自有代码必须零编译警告。方法引用转 `@Sendable` 闭包会触发数据竞争警告（Swift 6 下是错误），要用显式 `@Sendable` 闭包字面量
- `lazy var` 在 `@Observable` 类里编译不过（Observation 宏与 lazy 存储语义冲突），用 `let` + 显式 `init()`

```swift
import Foundation

/// 在多个音频源之间路由。
///
/// 自身实现 `AudioSource`，因此 `DictationSession` 完全不知道音频来自
/// 内置麦还是蓝牙遥控器——会话层一行不改。
///
/// **为什么不让 `DictationSession` 支持换源：** 音频源在会话构造时就接管了
/// `onFrame`，中途替换要处理正在录音、缓冲区归属等边界。M2 给
/// `previewEngine` 加运行时挂载已经付过一次这样的代价。
///
/// 路由器还让音频分叉点收敛到一处：M2 曾在 `AppModel` 里手工包一层
/// `onFrame` 把音频同时喂给预览处理器，两个源之后那段要写两遍。
@MainActor
final class AudioSourceRouter: AudioSource {
    enum Kind: Hashable {
        case microphone
        case bluetooth
    }

    var onFrame: (([Float]) -> Void)?
    var onStop: ((Error?) -> Void)?

    private(set) var active: Kind = .microphone
    private var isRunning = false
    private let sources: [Kind: AudioSource]

    init(sources: [Kind: AudioSource]) {
        self.sources = sources

        // 每个源的回调都接上，但只有当前活跃的那个会被转发出去。
        // 这样切换时不必重新绑定，也不会漏掉刚 stop 的源的收尾事件。
        for (kind, source) in sources {
            source.onFrame = { [weak self] samples in
                guard let self, self.active == kind else { return }
                self.onFrame?(samples)
            }
            source.onStop = { [weak self] error in
                guard let self, self.active == kind else { return }
                self.onStop?(error)
            }
        }
    }

    /// 选择本次会话使用的音频源。
    ///
    /// 运行中调用会被忽略——切换正在采集的源会让缓冲区里混进两个源的音频。
    func select(_ kind: Kind) {
        guard !isRunning else { return }
        guard sources[kind] != nil else { return }
        active = kind
    }

    func start() throws {
        guard !isRunning else { return }
        guard let source = sources[active] else {
            throw AudioSourceError.engineFailedToStart("音频源 \(active) 未接入")
        }
        try source.start()
        isRunning = true
    }

    func stop() {
        guard isRunning else { return }
        isRunning = false
        sources[active]?.stop()
    }
}
```

```swift
@Suite("ATVV 协议")
struct ATVVProtocolTests {

    // MARK: - 能力协商

    @Test("只接受 16 kHz")
    func acceptsOnly16k() {
        #expect(ATVVProtocol.supportsAudio(sampleRate: 16_000))
        #expect(!ATVVProtocol.supportsAudio(sampleRate: 8_000))
        #expect(!ATVVProtocol.supportsAudio(sampleRate: 48_000))
    }

    @Test("v1.0 及以上的开麦命令不带 codec 字节")
    func microphoneOpenForV1() {
        #expect(ATVVProtocol.microphoneOpen(version: 0x0100, codec: 0x02) == Data([0x0C, 0x00]))
    }

    @Test("v1.0 以下的开麦命令带 codec 字节")
    func microphoneOpenForLegacy() {
        #expect(ATVVProtocol.microphoneOpen(version: 0x0001, codec: 0x02) == Data([0x0C, 0x00, 0x02]))
    }

    @Test("MIC_EXTEND 仅在 v1.0 及以上可用")
    func extendOnlyForV1() {
        #expect(ATVVProtocol.microphoneExtend(version: 0x0100, sessionID: 7) == Data([0x0E, 7]))
        #expect(ATVVProtocol.microphoneExtend(version: 0x0001, sessionID: 7) == nil)
    }

    @Test("解析 v1.0 能力报文，codec 0x02 对应 16 kHz")
    func parsesV1Capabilities() throws {
        // 0x0B 头 + 版本 0x0100 + codecs 0x02 + interaction 0x03 + frameSize 0x0078(120)
        let data = Data([0x0B, 0x01, 0x00, 0x02, 0x03, 0x00, 0x78])

        #expect(caps.version == 0x0100)
        #expect(caps.selectedCodec == 0x02)
        #expect(caps.sampleRate == 16_000)
        #expect(caps.frameSize == 120)
    }

    @Test("codec 仅支持 0x01 时降为 8 kHz")
    func fallsBackTo8k() throws {
        let data = Data([0x0B, 0x01, 0x00, 0x01, 0x03, 0x00, 0x78])
        let caps = try #require(ATVVCapabilities.parse(data))

        #expect(caps.selectedCodec == 0x01)
        #expect(caps.sampleRate == 8_000)
    }

    @Test("帧长为 0 时取默认值 120")

        let data = Data([0x0B, 0x01, 0x00, 0x02, 0x03, 0x00, 0x00])

        #expect(caps.frameSize == 120)

        #expect(ATVVCapabilities.parse(Data([0x0A, 0x01, 0x00, 0x02, 0x03, 0x00, 0x78])) == nil)

        #expect(samples.count == 6)

    func zeroInputYieldsNearSilence() {
        let decoder = IMAADPCMDecoder()
        let samples = decoder.decode(Data(repeating: 0, count: 64))
        // nibble 0 的步进最小，预测器应停留在极小的幅度内

    @Test("解码器有状态：同样的输入在不同状态下产出不同结果")
```

```swift
import Foundation

/// 把蓝牙遥控器的音频包装成 `AudioSource`。
///
/// 它不直接持有蓝牙桥——桥的生命周期（连接、重连）比一次听写会话长得多，
/// 由 `RemoteCoordinator` 统一管理。本类型只负责在会话期间接收样本、
/// 归一化、转发。
///
/// ATVV 协商到 codec 0x02 时输出 16 kHz 单声道 Int16 PCM，与
/// `AudioFormat.sampleRate` 一致，**无需重采样**。
@MainActor
final class BluetoothRemoteSource: AudioSource {
    var onFrame: (([Float]) -> Void)?
    var onStop: ((Error?) -> Void)?

    private var isRunning = false

    func start() throws {
        isRunning = true
    }

    func stop() {
        guard isRunning else { return }
        isRunning = false
        onStop?(nil)
    }

    // MARK: - 由 RemoteCoordinator 驱动

    /// 蓝牙桥解码出一批样本时调用。
    ///
    /// 未启动时丢弃：桥的音频可能在会话开始前就到达（例如上一轮的尾包），
    /// 混进新会话的缓冲区会让开头多出一段无关音频。
    func deliver(_ samples: [Int16]) {
        guard isRunning else { return }
        onFrame?(Self.normalize(samples))
    }

    /// 录音期间遥控器断连。
    ///
    /// 以错误结束会话。`DictationSession` 只在 `.listening` 期间响应该错误；
    /// 若已进入转写阶段，音频已完整拿到手，中止反而是在丢字。
    func reportDisconnected() {
        guard isRunning else { return }
        isRunning = false
        onStop?(AudioSourceError.engineFailedToStart("遥控器已断开连接"))
    }

    // MARK: - 归一化

    /// Int16 PCM → Float，取值范围 -1…1。
    ///
    /// 除以 32768 而非 32767：Int16 的负半轴比正半轴多一个值，
    /// 用 32768 才能保证 -32768 恰好映射到 -1 且不溢出。
    nonisolated static func normalize(_ samples: [Int16]) -> [Float] {
        samples.map { Float($0) / 32_768 }
    }
}
```

```swift
import Foundation

/// 解析小米遥控器的 HID 输入报文。
///
/// 报文格式实测自上游 `RemoteButtons.swift`：报文 ID 必须为 1；若长度为 7
/// 且首字节等于报文 ID 则去掉首字节；其余按小端 `UInt16` 两两读出，
/// 非零者即为当前按下的 usage。
///
/// 本项目只需识别返回键，因此没有移植上游那套按键映射体系——那 1541 行的
/// 体量全在映射、手势识别、多设备档案上，而解析本身只有这十几行。
enum HIDReportParser {
    /// 遥控器的设备匹配标识。
    static let vendorID = 0x2717   // 小米
    static let productID = 0x32B8

    /// 返回键的 HID usage。
    ///
    /// **注意它不是标准的 Escape（0x29）**，因此系统不会把它变成普通按键，
    /// 现有的 Carbon 全局热键接不住，必须自行监听 HID。
    static let backButtonUsage: UInt16 = 0xF1

    static func usages(reportID: UInt32, data: Data) -> Set<UInt16>? {
        guard reportID == 1 else { return nil }

        var bytes = Array(data)
        if bytes.count == 7, bytes.first == UInt8(reportID) {
            bytes.removeFirst()
        }
        guard !bytes.isEmpty, bytes.count.isMultiple(of: 2) else { return nil }

        var result = Set<UInt16>()
        for index in stride(from: 0, to: bytes.count, by: 2) {
            let usage = UInt16(bytes[index]) | UInt16(bytes[index + 1]) << 8
            if usage != 0 { result.insert(usage) }
        }
        return result
    }
}
```

```swift
import Foundation
import IOKit.hid

/// 监听小米遥控器的返回键，用作取消。
///
/// **为什么自写而不移植：** 上游的 HID 子系统共 1541 行，体量全在按键映射、
/// 手势识别、多设备档案上。本项目只需识别一个 usage，值不当。
///
/// **为什么必须监听 HID：** 返回键的 usage 是 0xF1，不是标准 Escape（0x29），
/// 系统不会把它变成普通按键，现有的 Carbon 全局热键接不住。
@MainActor
final class RemoteHIDListener {
    /// 返回键被按下时触发。
    var onCancelPressed: (() -> Void)?

    private var manager: IOHIDManager?
    private var pressedUsages: Set<UInt16> = []

    /// 「输入监控」权限是否已授予。
    ///
    /// 未授予时听写**照常工作**——语音走 BLE，只需蓝牙权限。
    /// 仅返回键取消不可用。取消是锦上添花，听写是主路径。
    static func hasInputMonitoringAccess() -> Bool {
        IOHIDCheckAccess(kIOHIDRequestTypeListenEvent) == kIOHIDAccessTypeGranted
    }

    /// 请求「输入监控」权限。系统会弹出授权面板。
    @discardableResult
    static func requestInputMonitoringAccess() -> Bool {
        IOHIDRequestAccess(kIOHIDRequestTypeListenEvent)
    }

    func start() {
        guard manager == nil else { return }
        guard Self.hasInputMonitoringAccess() else {
            AppLogger.shared.log("未授予输入监控权限，遥控器返回键取消不可用")
            return
        }

        let manager = IOHIDManagerCreate(kCFAllocatorDefault, IOOptionBits(kIOHIDOptionsTypeNone))
        IOHIDManagerSetDeviceMatching(manager, [
            kIOHIDVendorIDKey as String: HIDReportParser.vendorID,
            kIOHIDProductIDKey as String: HIDReportParser.productID,
        ] as CFDictionary)

        let context = Unmanaged.passUnretained(self).toOpaque()
        // 管理器级的这个函数只有三个参数——带 buffer/length 的那个是
        // IOHIDDeviceRegisterInputReportCallback（设备级）。SDK 头文件写着
        // 「any enumerated device 发出输入报文时回调」，缓冲由它内部管理。
        IOHIDManagerRegisterInputReportCallback(
            manager,
            { context, _, _, _, reportID, report, reportLength in
                guard let context else { return }
                let listener = Unmanaged<RemoteHIDListener>.fromOpaque(context).takeUnretainedValue()
                let data = Data(bytes: report, count: reportLength)
                // IOHID 回调在被调度的 RunLoop 上；显式跳回主线程再改状态。
                DispatchQueue.main.async {
                    MainActor.assumeIsolated {
                        listener.handleReport(reportID: UInt32(reportID), data: data)
                    }
                }
            },
            context
        )
        IOHIDManagerScheduleWithRunLoop(manager, CFRunLoopGetMain(), CFRunLoopMode.defaultMode.rawValue)

        let result = IOHIDManagerOpen(manager, IOOptionBits(kIOHIDOptionsTypeNone))
        guard result == kIOReturnSuccess else {
            AppLogger.shared.log("HID 监听打开失败：\(result)")
            return
        }

        self.manager = manager
        AppLogger.shared.log("HID 监听已启动")
    }

    func stop() {
        guard let manager else { return }
        IOHIDManagerUnscheduleFromRunLoop(manager, CFRunLoopGetMain(), CFRunLoopMode.defaultMode.rawValue)
        IOHIDManagerClose(manager, IOOptionBits(kIOHIDOptionsTypeNone))
        self.manager = nil
        pressedUsages = []
    }

    private func handleReport(reportID: UInt32, data: Data) {
        guard let current = HIDReportParser.usages(reportID: reportID, data: data) else { return }
        let previous = pressedUsages
        pressedUsages = current

        if Self.didPress(usage: HIDReportParser.backButtonUsage, previous: previous, current: current) {
            onCancelPressed?()
        }
    }

    /// 判断某个 usage 是否在本次报文中「刚被按下」。
    ///
    /// 抽成纯函数以便单测——真实 HID 设备无法在测试中构造。
    nonisolated static func didPress(
        usage: UInt16,
        previous: Set<UInt16>,
        current: Set<UInt16>
    ) -> Bool {
        current.contains(usage) && !previous.contains(usage)
    }
}
```

```swift
import Foundation

/// 把遥控器的事件翻译成会话动作。
///
/// 这是本里程碑的核心需求所在——用户原话：
///
/// > 按下语音键，相当于按下了 ⌥D；松开语音键，相当于又按了一次 ⌥D。
///
/// 因此这里的映射极简单：`handleVoiceStart` → 开始会话，
/// `handleVoiceStop` → 结束会话，返回键 → 取消。下游一个字都不变。
///
/// 只接收语义化事件而不直接持有蓝牙桥，是为了让这段映射可以单元测试——
/// 真实的桥需要外设。由 `AppModel` 负责把 delegate 回调翻译成这些调用。
@MainActor
final class RemoteCoordinator {
    /// 语音键按下，请求开始会话。
    var onStartSession: (() -> Void)?
    /// 语音键松开，请求结束会话并转写。
    var onFinishSession: (() -> Void)?
    /// 返回键按下，请求取消会话。
    var onCancelSession: (() -> Void)?

    let source: BluetoothRemoteSource

    /// 本次语音是否仍在进行。用于过滤重复事件与取消后的收尾事件。
    private var isVoiceActive = false

    init(source: BluetoothRemoteSource) {
        self.source = source
    }

    func handleVoiceStart() {
        guard !isVoiceActive else { return }
        isVoiceActive = true
        onStartSession?()
    }

    func handleVoiceStop() {
        guard isVoiceActive else { return }
        isVoiceActive = false
        onFinishSession?()
    }

    func handleCancelPressed() {
        guard isVoiceActive else { return }
        // 取消后把状态清掉，否则用户随后松开语音键会再触发一次结束。
        isVoiceActive = false
        onCancelSession?()
    }

    func handleDecoded(_ samples: [Int16]) {
        source.deliver(samples)
    }

    func handleDisconnected() {
        isVoiceActive = false
        source.reportDisconnected()
    }
}
```

```swift
import Foundation

/// 在长时间录音期间周期性续期 ATVV 会话。
///
/// RC003 按住语音键约 60 秒后固件会主动结束会话。ATVV 的 `MIC_EXTEND`
/// （`0x0E`）用于续期，但需要有人周期性发送。
///
/// **该行为未经上游真机验收**——上游文档记录「RC003 是否能因此录过 60 秒
/// 仍需真机验收」，状态挂在「等待人工验收」。本项目有硬件，M3 验收时首次确认。
///
/// 把判断与真实计时器分开，是为了不用等真实时间就能测——等 60 秒的测试
/// 没人会跑第二次。
@MainActor
final class VoiceSessionKeepalive {
    /// 续期间隔。10 秒在 60 秒的固件切断前留出 6 次机会，
    /// 单次写入失败不至于让整个保活失效。
    static let interval: TimeInterval = 10
    /// 单次会话的上限。沿用上游的试验安全值，**不是固件限制**。
    static let maxDuration: TimeInterval = 180

    /// 该发送 `MIC_EXTEND` 了。
    var onExtend: (() -> Void)?
    /// 达到上限，该主动结束会话了。
    var onTimeout: (() -> Void)?

    private var startedAt: Date?
    private var extendCount = 0
    private var timer: Timer?

    func start(now: Date = Date()) {
        startedAt = now
        extendCount = 0

        timer?.invalidate()
        // 每秒查一次即可——判断逻辑基于绝对时刻，不依赖 tick 的精确性。
        timer = Timer.scheduledTimer(withTimeInterval: 1, repeats: true) { [weak self] _ in
            Task { @MainActor [weak self] in
                self?.tick(now: Date())
            }
        }
    }

    func stop() {
        startedAt = nil
        timer?.invalidate()
        timer = nil
    }

    /// 生产环境由计时器每秒调用；测试直接调用并传入构造的时刻。
    func tick(now: Date) {
        guard let startedAt else { return }
        let elapsed = now.timeIntervalSince(startedAt)

        if elapsed >= Self.maxDuration {
            stop()
            onTimeout?()
            return
        }

        let due = Int(elapsed / Self.interval)
        while extendCount < due {
            extendCount += 1
            onExtend?()
        }
    }
}
```

## 风险与备选

### 风险 1：移植的状态机在本项目环境下行为不同

上游把桥嵌在一个有设置系统、按键映射、多设备档案的应用里。本项目只取音频路径，可能触及上游未走过的分支——例如从未调用 `requestMicrophoneOpen` 之外的控制命令。

若真机上出现连接不稳或音频断续，**先读日志**（桥内有 35 处日志点，已全部保留），不要急于改移植来的代码。它在上游是经过真机验证的。

### 风险 2：MIC_EXTEND 保活可能无效

上游明确标注该行为未经真机验收。若实测发现仍在 60 秒被切断，说明保活策略对 RC003 固件无效。

**这不阻塞 M3 验收** —— 60 秒对遥控器的目标场景（写 prompt、发消息）足够，长文本来就走内置麦。如实记录实测时长即可。

### 风险 3：输入监控权限的开发期反复

TCC 授权绑定应用签名，而 `build-app.sh` 每次都重新 ad-hoc 签名。**每次重新打包后可能都要重新授权输入监控**，这会让开发期很烦。

若确实频繁失效，可考虑开发期用固定的自签名证书。但先按现状做，确认烦到什么程度再说——过早优化开发流程不值得。

### 风险 4：蓝牙与内置麦的音频源冲突

`AudioSourceRouter` 保证一次只有一个源活跃，且运行中不允许切换。但若蓝牙桥在会话进行中推来音频（例如上一轮的尾包），`BluetoothRemoteSource` 会在未启动时丢弃它们。

Task 5 有对应测试。若真机上仍出现开头多一段无关音频，检查 `deliver` 的 `isRunning` 守卫是否被绕过。
