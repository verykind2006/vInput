# M4 本地 LLM 校正层 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在转写与注入之间插入一层，用本地 LLM 修正 Whisper 听错的字词，且由拼音闸门保证它不会改写用户的措辞。

**Architecture:** 新增 `Corrector` protocol（第四条接缝），实现只负责产出「替换清单」；拼音闸门是独立纯函数，套在任何实现的输出上，逐条判定同音才放行。任一环节失败一律注入原始转写。

**Tech Stack:** Swift 6 / Swift Testing / MLX Swift（`MLXLLM` + `MLXLMCommon`，tag 2.29.1）/ `CFStringTransform`

**三条既有规则**（贯穿全项目，本里程碑必须遵守）：

1. 规则一：场景风格由前台应用决定（M5 的事，本里程碑不碰）

```swift
import Foundation

/// 汉字到拼音的转换，用于判定两段文本是否同音。
///
/// 用系统内置的 ICU 音译器，无第三方依赖，与繁简转换
/// （`ChineseScript`）使用同一套机制。
enum Pinyin {
    /// 转成小写、无声调的拼音，音节间以单个空格分隔。
    ///
    /// **忽略声调是有意的。** 同音错字绝大多数是声调差异
    /// （yào 耀 / yáo 遥），要求声调一致会把最该修的那一类全部拦掉。
    ///
    /// **拉丁字母与数字原样穿过。** 因此 `useEffect` 与 `useState`
    /// 靠同一套比对就能区分，不需要为非汉字另设一条规则——
    /// 少一条规则就少一处出错的地方。
    static func toneless(_ text: String) -> String {
        let buffer = NSMutableString(string: text) as CFMutableString
        // 汉字 → 带声调拼音
        CFStringTransform(buffer, nil, kCFStringTransformMandarinLatin, false)
        // 去掉声调符号（ā á ǎ à → a）
        CFStringTransform(buffer, nil, kCFStringTransformStripDiacritics, false)

        return (buffer as String)
            .lowercased()
            // 音译器在音节间插入空格，数量随上下文变化，统一压成单个空格。
            // 保留空格而非全部删除：删掉会让「西安」(xi an) 与「先」(xian)
            // 混为一谈，那是两个不同的词。
            .split(separator: " ", omittingEmptySubsequences: true)
            .joined(separator: " ")
    }
}
```

```swift
import Foundation

/// 一条替换：把转写中的 `original` 换成 `replacement`。
struct CorrectionEdit: Equatable, Sendable {
    let original: String
    let replacement: String
}

enum CorrectorError: Error, Equatable {
    /// 模型尚未加载。
    case modelNotReady
    /// 底层引擎报错。
    case engineFailed(String)
    /// 推理超时。
    case timedOut
}

/// 找出转写中听错的字词，给出替换清单。
///
/// **实现只负责提出建议，不负责判断建议是否安全**——那是
/// `CorrectionGate` 的职责，且它位于本 protocol 之外，
/// 任何实现（本地、将来的云端）共用同一道闸门。
protocol Corrector: Sendable {
    /// 确保模型已加载。可重复调用，已就绪时立即返回。
    func prepare() async throws

    /// 针对一段转写文本给出替换清单。可能为空（没发现错误）。
    func edits(for text: String) async throws -> [CorrectionEdit]
}
```

创建 `Sources/vInput/Correct/CorrectionEditParser.swift`：

```swift
import Foundation

/// 把模型输出的替换清单解析成结构化条目。
///
/// 格式是一行一条 `原文→替换`。选这个格式而非 JSON：4B 量级的模型
/// 产出合法 JSON 的可靠性不足，而这个格式几乎不可能写错。
///
/// **格式本身就是第一道保险**——模型只能逐词替换，结构上无法重写整句。
enum CorrectionEditParser {
    /// 认这几种箭头。模型在中英文语境下会写出不同变体，
    /// 与其要求它精确，不如让解析宽容：宽容的代价是多认几种写法，
    /// 严格的代价是整次校正作废。
    private static let arrows = ["→", "=>", "->", "⇒"]

    static func parse(_ output: String) -> [CorrectionEdit] {
        output.split(separator: "\n", omittingEmptySubsequences: true).compactMap { line in
            parseLine(String(line))
        }
    }

    private static func parseLine(_ line: String) -> CorrectionEdit? {
        guard let arrow = arrows.first(where: { line.contains($0) }) else { return nil }

        let parts = line.components(separatedBy: arrow)
        // 多于两段说明一行里有多个箭头，切分点无法确定。整行丢弃：
        // 猜错的代价是改错用户的话，不猜的代价只是少改一处。
        guard parts.count == 2 else { return nil }

        let original = parts[0].trimmingCharacters(in: .whitespaces)
        let replacement = parts[1].trimmingCharacters(in: .whitespaces)

        guard !original.isEmpty, !replacement.isEmpty, original != replacement else {
            return nil
        }
        return CorrectionEdit(original: original, replacement: replacement)
    }
}
```

```swift
import Foundation

/// 判定一条替换是否安全，并把放行的替换应用到文本上。
///
/// **这是唯一挡在「LLM 改写用户说的话」前面的东西。**
/// 它刻意位于 `Corrector` protocol 之外：M4 只做本地实现，云端排在
/// 其后，若把闸门写进某个实现内部，接云端时就得重写一遍——而两份
/// 闸门就会有两种松紧。
///
/// 全部是纯函数，不依赖模型，可穷举测试。
enum CorrectionGate {
    /// 替换前后读音必须一致，否则不是「改错字」而是「改写」。
    static func allows(_ edit: CorrectionEdit) -> Bool {
        Pinyin.toneless(edit.original) == Pinyin.toneless(edit.replacement)
    }
}
```

```swift
    /// 应用替换的结果。`applied` 与 `rejected` 供日志使用——
    /// 闸门的松紧要能从日常使用的日志中判断，而不是靠专门安排测试。
    struct Outcome: Equatable {
        let text: String
        let applied: [CorrectionEdit]
        let rejected: [CorrectionEdit]
    }

    /// 把通过闸门的替换应用到文本上。
    static func apply(_ edits: [CorrectionEdit], to text: String) -> Outcome {
        var result = text
        var applied: [CorrectionEdit] = []
        var rejected: [CorrectionEdit] = []

        // 按原文长度降序：短片段先替换会破坏长片段的匹配，
        // 例如「据裤→据库」先跑，「数据裤」就再也匹配不上了。
        for edit in edits.sorted(by: { $0.original.count > $1.original.count }) {
            guard allows(edit) else {
                rejected.append(edit)
                continue
            }
            // 原文片段必须原样存在。模型偶尔会「引用」一个它自己改写过的
            // 片段，那种条目无从定位，宁可不改。
            guard result.contains(edit.original) else {
                rejected.append(edit)
                continue
            }
            // 全部出现处一起替换：同一个词在一句话里听错两次会错成同一个
            // 样子，只改第一处会留下一个自相矛盾的句子。
            result = result.replacingOccurrences(of: edit.original, with: edit.replacement)
            applied.append(edit)
        }

        return Outcome(text: result, applied: applied, rejected: rejected)
    }
```

```swift
import Foundation

/// 串起「求建议 → 解析 → 过闸 → 应用」，并保证任何失败都退回原文。
///
/// **校正是锦上添花，绝不允许它的失败影响主路径。** 与预览引擎在 M2
/// 的处理方式一致：出错只记日志，不上报为会话错误，因为用户已经说出的
/// 内容必须原样落到光标处（规则二·永不丢字）。
struct CorrectionPipeline: Sendable {
    private let corrector: Corrector
    private let timeout: Duration

    init(corrector: Corrector, timeout: Duration = .seconds(3)) {
        self.corrector = corrector
        self.timeout = timeout
    }

    /// 返回校正后的文本。任何环节失败都返回入参原文，本函数不抛错。
    func correct(_ text: String) async -> String {
        guard !text.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty else {
            return text
        }

        let edits: [CorrectionEdit]
        do {
            edits = try await withTimeout(timeout) {
                try await corrector.prepare()
                return try await corrector.edits(for: text)
            }
        } catch {
            AppLogger.shared.log("校正跳过：\(error)")
            return text
        }

        guard !edits.isEmpty else { return text }

        let outcome = CorrectionGate.apply(edits, to: text)
        logOutcome(outcome)
        return outcome.text
    }

    /// 记录采纳与拦下的替换，供判断闸门松紧。
    ///
    /// 只记替换对，不记全文——日志默认不含转写内容（见设计文档「隐私」）。
    private func logOutcome(_ outcome: CorrectionGate.Outcome) {
        guard !outcome.applied.isEmpty || !outcome.rejected.isEmpty else { return }
        let describe: ([CorrectionEdit]) -> String = { edits in
            edits.map { "\($0.original)→\($0.replacement)" }.joined(separator: " ")
        }
        AppLogger.shared.log(
            "校正 采纳=[\(describe(outcome.applied))] 拦下=[\(describe(outcome.rejected))]"
        )
    }

    /// 给一段异步工作加超时。超时后抛 `CorrectorError.timedOut`。
    ///
    /// 用 `TaskGroup` 而非 `Task.detached` + 定时器：组内任一子任务返回后
    /// `cancelAll()` 会取消另一个，推理任务不会在后台继续烧 CPU。
    private func withTimeout<T: Sendable>(
        _ duration: Duration,
        operation: @escaping @Sendable () async throws -> T
    ) async throws -> T {
        try await withThrowingTaskGroup(of: T.self) { group in
            group.addTask { try await operation() }
            group.addTask {
                try await Task.sleep(for: duration)
                throw CorrectorError.timedOut
            }
            defer { group.cancelAll() }
            guard let first = try await group.next() else {
                throw CorrectorError.timedOut
            }
            return first
        }
    }
}
```

```swift
/// 给校正模型的指令。
///
/// 提示词只是第一层约束，真正的保障是拼音闸门——提示词写得再好，
/// 4B 模型也会时不时自作主张。因此这里不追求面面俱到，只求把最常见的
/// 两种失败模式（输出整句、翻译英文术语）压下去。
enum CorrectionPrompt {
    /// 没有发现错误时约定的输出。刻意选一个不含箭头的词，
    /// 于是它天然被解析成空清单，不需要额外的特判分支。
    static let noChangeMarker = "无"

    static let instructions = """
        你是中文语音转写的校对助手。用户给你一段语音识别结果，其中可能有同音字错误。

        规则：
        1. 只输出替换清单，每行一条，格式为 原文→正确文本
        2. 只改同音或近音的错字，绝不改写句子、语序、标点
        3. 英文单词、代码标识符、专有名词一律保持原样，不要翻译成中文
        4. 没有发现错误时，只输出：\(noChangeMarker)

        示例：
        输入：小米耀空气很好用
        输出：耀空气→遥控器

        输入：今天天气不错
        输出：\(noChangeMarker)
        """

    static func user(for text: String) -> String {
        "输入：\(text)\n输出："
    }
}
```

- [ ] **Step 4: 实现校正器**

创建 `Sources/vInput/Correct/MLXCorrector.swift`：

```swift
import Foundation
import MLXLLM
import MLXLMCommon

/// 基于 MLX 的本地校正器。
///
/// 用 actor 而非 class：模型加载与推理都不可重入，两次会话同时触发时
/// 第二个必须排队而不是并发进入。与 `WhisperKitTranscriber` 同一考量。
actor MLXCorrector: Corrector {
    /// 本地模型目录。为 nil 时按 Hugging Face 标识符下载。
    ///
    /// 优先支持本地目录，与 Whisper 同一考量：内置下载器在丢包网络下会
    /// 整体超时放弃，本仓库因此一直用预先拉好的本地模型。
    private let modelDirectory: URL?
    private let modelID: String
    private var container: ModelContainer?

    init(
        modelDirectory: URL? = nil,
        modelID: String = "mlx-community/Qwen3-4B-Instruct-2507-4bit"
    ) {
        self.modelDirectory = modelDirectory
        self.modelID = modelID
    }

    func prepare() async throws {
        guard container == nil else { return }
        do {
            container = if let modelDirectory {
                try await loadModelContainer(directory: modelDirectory)
            } else {
                try await loadModelContainer(id: modelID)
            }
        } catch {
            throw CorrectorError.engineFailed(error.localizedDescription)
        }
    }

    func edits(for text: String) async throws -> [CorrectionEdit] {
        try await prepare()
        guard let container else { throw CorrectorError.modelNotReady }

        // 逐字段赋值而非用带标签的构造器：GenerateParameters 的字段在
        // 版本间增删过，逐字段赋值不受参数顺序与标签变化影响。
        var parameters = GenerateParameters()
        // 校正要的是确定性，不是创造力。同一句话每次都该得到同样的结果。
        parameters.temperature = 0
        // 替换清单本就极短。设上限是为了让「模型开始滔滔不绝」这种失败
        // 快速结束，而不是拖到 3 秒超时才被打断。
        parameters.maxTokens = 256

        // **每次新建 ChatSession。** 它内部持有对话历史，复用会让上一句
        // 转写污染下一句的校正。M2 曾因复用 AudioStreamTranscriber 导致
        // 第二次会话显示上次的文字，这是同一类错误。
        let session = ChatSession(
            container,
            instructions: CorrectionPrompt.instructions,
            generateParameters: parameters
        )

        let output: String
        do {
            output = try await session.respond(to: CorrectionPrompt.user(for: text))
        } catch {
            throw CorrectorError.engineFailed(error.localizedDescription)
        }

        return CorrectionEditParser.parse(output)
    }
}
```

**M4 的验收标准：同一句话，开关校正能看出差别。**

1. 菜单栏 →「指定校正模型…」，选择本地 MLX 模型目录
2. 菜单栏 →「校正（关）」点开，变为「校正（开）」
3. 说一句包含易错词的话（例如「小米遥控器很好用」）
4. 关闭校正，说同一句话，对比结果

日志中每次校正会记录 `校正 采纳=[…] 拦下=[…]`，据此判断闸门松紧：

- 拦下的条目里若有本该采纳的，说明闸门过严
- 采纳的条目里若有改坏原意的，说明闸门过松

**若 4B 模型效果不佳**，通过「指定校正模型…」换更大的模型（如 8B），无需改代码——这正是该菜单项在 M4 属于必需而非锦上添花的原因。
