# vInput M2 实施计划：HUD 与实时预览

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 说话时在屏幕底部的浮窗里看到文字逐渐出现，同时显示录音状态、时长与音量波形，并支持 `Esc` 取消。

**Architecture:** 音频在 `AudioSource` 之后分叉：一路进 `AudioBuffer` 供松手后的全量转写，一路进自实现的 `AudioProcessing` 适配层，喂给 WhisperKit 自带的 `AudioStreamTranscriber` 产出流式预览。预览只进 HUD，从不注入。

**Tech Stack:** WhisperKit `AudioStreamTranscriber`（流式转写）、AppKit `NSPanel`（无焦点浮窗）、SwiftUI（HUD 内容）、Carbon HIToolbox（`Esc` 全局热键）。

**4. `AudioProcessing` 协议的全部要求**（`AudioProcessor.swift`）：

```swift

    static func loadAudio(at:channelMode:) async -> [Result<[Float], Swift.Error>]
    static func padOrTrimAudio(fromArray:startAt:toLength:saveSegment:) -> MLMultiArray?

    var relativeEnergy: [Float] { get }
    var relativeEnergyWindow: Int { get set }
    func startRecordingLive(inputDeviceID: DeviceID?, callback: (([Float]) -> Void)?) throws
    func startStreamingRecordingLive(inputDeviceID: DeviceID?) -> (AsyncThrowingStream<[Float], Error>, AsyncThrowingStream<[Float], Error>.Continuation)
    func pauseRecording()
    func stopRecording()
    func resumeRecordingLive(inputDeviceID: DeviceID?, callback: (([Float]) -> Void)?) throws
```

**5. 不能通过继承注入。** `AudioProcessor` 虽是 `open class`，但除 `padOrTrim` 外其方法均为 `public` 而非 `open`，跨模块无法重写。必须自行实现整个协议。

**6. 能量计算可复用，不要自己写：**

```swift
public static func calculateAverageEnergy(of signal: [Float]) -> Float
public static func calculateRelativeEnergy(of signal: [Float], relativeTo reference: Float?) -> Float
```

`AudioStreamTranscriber` 用 `relativeEnergy` 配合 `silenceThreshold: 0.3` 做静音判断。**自己另写一套归一化会让流式的静音判断失准**，必须用上面这个静态方法。

## 两个必须正确处理的风险

### 风险 A：流式与全量共享同一套解码器实例

流式转写器用的 `textDecoder` / `audioEncoder` 等，与 `WhisperKitTranscriber` 全量转写用的是**同一批对象**。两者并发执行会在解码器状态上产生数据竞争。

**因此必须保证严格不重叠**：预览只在 `.listening` 期间运行，全量转写只在预览彻底停止之后开始。

### 风险 B：`stopStreamTranscription()` 不等待循环退出

它只把 `isRecording` 置 false，`realtimeLoop()` 会在**当前这轮转写跑完之后**才退出。若此时立刻发起全量转写，就会撞上风险 A。

**正确的停止姿势**——持有运行 `startStreamTranscription()` 的 Task，停止后 await 它：

```swift
// 启动
streamTask = Task { try await streamTranscriber.startStreamTranscription() }

// 停止：两步缺一不可
await streamTranscriber.stopStreamTranscription()
_ = await streamTask?.result      // 等循环真正退出，确保解码器空闲
streamTask = nil
```

```swift
import Foundation

/// 推送给 HUD 的一次预览快照。
struct PreviewText: Equatable, Sendable {
    /// 已确认的文本，不会再被改写。
    let confirmed: String
    /// 未确认的文本，后续可能被修正。
    let unconfirmed: String
    /// 归一化到 0…1 的最近能量值，供音量波形使用。
    let energy: [Float]

    static let empty = PreviewText(confirmed: "", unconfirmed: "", energy: [])
}

enum PreviewEngineError: Error, Equatable {
    /// 底层模型尚未就绪。
    case notReady
    /// 流式引擎内部错误。
    case streamFailed(String)
}

/// 边录边转写，产出供 HUD 显示的预览文本。
///
/// 预览是锦上添花：本协议的任何失败都不得影响主转写路径。
/// `DictationSession` 会捕获全部错误、关闭预览、让录音继续。
protocol PreviewEngine: AnyObject, Sendable {
    /// 每产出一次新预览触发。回调在任意线程，调用方需自行调度到主线程。
    var onUpdate: (@Sendable (PreviewText) -> Void)? { get set }

    /// 开始流式转写。
    func start() async throws

    /// 停止流式转写。
    ///
    /// **必须等到底层推理循环真正退出才返回**——调用方会紧接着发起全量
    /// 转写，而两者共享同一套解码器实例，重叠会产生数据竞争。
    func stop() async
}
```

```swift
import Foundation
import Testing
@testable import vInput

/// 由测试代码手动驱动的预览引擎。
final class FakePreviewEngine: PreviewEngine, @unchecked Sendable {
    var onUpdate: (@Sendable (PreviewText) -> Void)?

    private(set) var startCallCount = 0
    private(set) var stopCallCount = 0
    /// 记录 stop 被调用时的时刻，用于断言「先停预览再转写」。
    private(set) var stopOrder: Int?

    /// 设置后，`start()` 抛出该错误。
    var startError: Error?
    /// `stop()` 的人为耗时，用于验证调用方确实在等它。
    var stopDelay: Duration = .zero

    /// 供测试统计全局调用顺序。
    static let orderCounter = OrderCounter()

    func start() async throws {
        startCallCount += 1
        if let startError { throw startError }
    }

    func stop() async {
        stopCallCount += 1
        stopOrder = Self.orderCounter.next()
        if stopDelay > .zero { try? await Task.sleep(for: stopDelay) }
    }

    /// 模拟产出一次预览。
    func emit(confirmed: String, unconfirmed: String = "", energy: [Float] = []) {
        onUpdate?(PreviewText(confirmed: confirmed, unconfirmed: unconfirmed, energy: energy))
    }
}

/// 线程安全的自增计数器，用于断言调用先后顺序。
final class OrderCounter: @unchecked Sendable {
    private var value = 0
    private let lock = NSLock()

    func next() -> Int {
        lock.lock(); defer { lock.unlock() }
        value += 1
        return value
    }

    func reset() {
        lock.lock(); defer { lock.unlock() }
        value = 0
    }
}

@Suite("FakePreviewEngine")
struct FakePreviewEngineTests {
    @Test("emit 会把预览推给 onUpdate")
    func emitDeliversPreview() {
        let engine = FakePreviewEngine()
        var received: PreviewText?
        engine.onUpdate = { received = $0 }

        engine.emit(confirmed: "已确认", unconfirmed: "未确认", energy: [0.5])

        #expect(received == PreviewText(confirmed: "已确认", unconfirmed: "未确认", energy: [0.5]))
    }

    @Test("start 抛出预设的错误")
    func startPropagatesError() async {
        let engine = FakePreviewEngine()
        engine.startError = PreviewEngineError.notReady

        await #expect(throws: PreviewEngineError.notReady) {
            try await engine.start()
        }
    }

    @Test("stop 记录调用次数")
    func stopCounts() async {
        let engine = FakePreviewEngine()
        await engine.stop()
        await engine.stop()
        #expect(engine.stopCallCount == 2)
    }
}
```

创建 `Sources/vInput/Preview/SourceBackedAudioProcessor.swift`：

```swift
import AVFoundation
import CoreML
import Foundation
import WhisperKit

/// 实现 WhisperKit 的 `AudioProcessing`，但音频由外部推入而非自行采集。
///
/// 存在的理由：`AudioStreamTranscriber` 通过该协议取音频，默认实现
/// (`AudioProcessor`) 会自己打开麦克风。我们需要它消费 `AudioSource`
/// 产出的帧——这样 M3 接入蓝牙遥控器时，流式预览无需任何改动即可工作。
///
/// 不能通过继承 `AudioProcessor` 实现：该类虽为 `open`，但除 `padOrTrim`
/// 外其方法均为 `public` 而非 `open`，跨模块无法重写。
///
/// 线程安全：`AudioSource` 在主线程推入，`AudioStreamTranscriber` 在其
/// 自身 actor 上读取，因此内部状态用锁保护。
final class SourceBackedAudioProcessor: AudioProcessing, @unchecked Sendable {
    private let lock = NSLock()
    private var samples = ContiguousArray<Float>()
    private var energies: [Float] = []

    var relativeEnergyWindow: Int = 20

    var audioSamples: ContiguousArray<Float> {
        lock.lock(); defer { lock.unlock() }
        return samples
    }

    var relativeEnergy: [Float] {
        lock.lock(); defer { lock.unlock() }
        return energies
    }

    // MARK: - 外部投喂

    /// 由 `AudioSource` 的回调推入一批样本。
    func append(_ chunk: [Float]) {
        guard !chunk.isEmpty else { return }

        // 复用 WhisperKit 的能量算法。AudioStreamTranscriber 用
        // relativeEnergy 配合 silenceThreshold(0.3) 做静音判断，
        // 自己另写一套归一化会让它的判断失准。
        let relative = AudioProcessor.calculateRelativeEnergy(of: chunk, relativeTo: nil)

        lock.lock()
        samples.append(contentsOf: chunk)
        energies.append(relative)
        lock.unlock()
    }

    /// 会话结束时清空，为下一次录音做准备。
    func reset() {
        lock.lock()
        samples.removeAll(keepingCapacity: true)
        energies.removeAll(keepingCapacity: true)
        lock.unlock()
    }

    // MARK: - AudioProcessing 必需成员

    func purgeAudioSamples(keepingLast keep: Int) {
        lock.lock(); defer { lock.unlock() }
        guard samples.count > keep else { return }
        samples.removeFirst(samples.count - keep)
    }

    // 以下生命周期方法在本实现里是空操作：音频由 AudioSource 驱动，
    // 不由本对象采集。保留空实现以满足协议。
    func startRecordingLive(inputDeviceID: DeviceID?, callback: (([Float]) -> Void)?) throws {}
    func pauseRecording() {}
    func stopRecording() {}
    func resumeRecordingLive(inputDeviceID: DeviceID?, callback: (([Float]) -> Void)?) throws {}

    func startStreamingRecordingLive(
        inputDeviceID: DeviceID?
    ) -> (AsyncThrowingStream<[Float], Error>, AsyncThrowingStream<[Float], Error>.Continuation) {
        // 不支持该模式——AudioStreamTranscriber 走的是 startRecordingLive 路径。
        var continuation: AsyncThrowingStream<[Float], Error>.Continuation!
        let stream = AsyncThrowingStream<[Float], Error> { continuation = $0 }
        continuation.finish()
        return (stream, continuation)
    }

    func padOrTrim(
        fromArray audioArray: [Float],
        startAt startIndex: Int,
        toLength frameLength: Int
    ) -> (any AudioProcessorOutputType)? {
        AudioProcessor.padOrTrimAudio(
            fromArray: audioArray,
            startAt: startIndex,
            toLength: frameLength,
            saveSegment: false
        )
    }

    // MARK: - 静态成员，全部转发给 WhisperKit 的现成实现

    static func loadAudio(
        fromPath audioFilePath: String,
        channelMode: ChannelMode,
        startTime: Double?,
        endTime: Double?,
        maxReadFrameSize: AVAudioFrameCount?
    ) throws -> AVAudioPCMBuffer {
        try AudioProcessor.loadAudio(
            fromPath: audioFilePath,
            channelMode: channelMode,
            startTime: startTime,
            endTime: endTime,
            maxReadFrameSize: maxReadFrameSize
        )
    }

    static func loadAudio(
        at audioPaths: [String],
        channelMode: ChannelMode
    ) async -> [Result<[Float], Swift.Error>] {
        await AudioProcessor.loadAudio(at: audioPaths, channelMode: channelMode)
    }

    static func padOrTrimAudio(
        fromArray audioArray: [Float],
        startAt startIndex: Int,
        toLength frameLength: Int,
        saveSegment: Bool
    ) -> MLMultiArray? {
        AudioProcessor.padOrTrimAudio(
            fromArray: audioArray,
            startAt: startIndex,
            toLength: frameLength,
            saveSegment: saveSegment
        )
    }
}
```

```swift
/// 能够产出流式预览引擎的转写器。
///
/// 单独成一个协议而非并入 `Transcriber`：`FakeTranscriber` 与未来可能的
/// 云端转写器都不需要这个能力，不该被迫实现它。
protocol PreviewCapable {
    /// 基于当前已加载的模型构造一个预览引擎。
```

创建 `Sources/vInput/Preview/StreamingPreviewEngine.swift`：

```swift
import Foundation
import WhisperKit

/// 把 WhisperKit 的 `AudioStreamTranscriber` 适配成 `PreviewEngine`。
///
/// 复用 WhisperKit 的流式引擎而非自己写：流式转写的难点不是定时调用，
/// 而是窗口边界的文本拼接去重、以及判断哪部分文本已稳定。自己实现
/// 大概率会在中文分词边界上出问题。
final class StreamingPreviewEngine: PreviewEngine, @unchecked Sendable {
    var onUpdate: (@Sendable (PreviewText) -> Void)?

    private let transcriber: AudioStreamTranscriber
    private let processor: SourceBackedAudioProcessor
    private let lock = NSLock()
    private var streamTask: Task<Void, Error>?

    init(
        audioEncoder: any AudioEncoding,
        featureExtractor: any FeatureExtracting,
        segmentSeeker: any SegmentSeeking,
        textDecoder: any TextDecoding,
        tokenizer: any WhisperTokenizer,
        processor: SourceBackedAudioProcessor,
        decodingOptions: DecodingOptions
    ) {
        self.processor = processor

        // 回调要在 transcriber 构造时传入，而此时 self 还不可用，
        // 因此先建一个盒子，构造完再把真正的转发函数放进去。
        let box = CallbackBox()
        self.transcriber = AudioStreamTranscriber(
            audioEncoder: audioEncoder,
            featureExtractor: featureExtractor,
            segmentSeeker: segmentSeeker,
            textDecoder: textDecoder,
            tokenizer: tokenizer,
            audioProcessor: processor,
            decodingOptions: decodingOptions,
            stateChangeCallback: { _, newState in
                box.handler?(newState)
            }
        )
        box.handler = { [weak self] state in
            guard let self else { return }
            self.onUpdate?(Self.makePreview(from: state))
        }
    }

    /// 把 WhisperKit 的流式状态转换成 HUD 需要的形状。
    static func makePreview(from state: AudioStreamTranscriber.State) -> PreviewText {
        let confirmed = state.confirmedSegments.map(\.text).joined()
        let unconfirmed = state.unconfirmedSegments.map(\.text).joined()
        return PreviewText(
            confirmed: ChineseScript.toSimplified(confirmed.trimmingCharacters(in: .whitespaces)),
            unconfirmed: ChineseScript.toSimplified(unconfirmed.trimmingCharacters(in: .whitespaces)),
            energy: state.bufferEnergy
        )
    }

    func start() async throws {
        processor.reset()
        let task = Task { [transcriber] in
            try await transcriber.startStreamTranscription()
        }
        lock.lock(); streamTask = task; lock.unlock()
    }

    /// 停止并**等待推理循环真正退出**。
    ///
    /// `stopStreamTranscription()` 只把 isRecording 置 false，循环会在当前
    /// 这轮转写跑完之后才退出。调用方紧接着就要发起全量转写，而两者共享
    /// 同一套解码器实例——不等就会撞上数据竞争。
    func stop() async {
        await transcriber.stopStreamTranscription()

        lock.lock(); let task = streamTask; streamTask = nil; lock.unlock()
        _ = await task?.result
    }
}

/// 承载回调的盒子。构造 AudioStreamTranscriber 时 self 尚不可用，
/// 需要一个中间层把回调转发到构造完成后的实例。
private final class CallbackBox: @unchecked Sendable {
    var handler: (@Sendable (AudioStreamTranscriber.State) -> Void)?
}
```

```swift
import Foundation
import Observation

/// HUD 的展示逻辑。
///
/// 全部计算做成 `nonisolated static` 纯函数，视图只负责画——
/// 这样展示逻辑可以完整单测，而 SwiftUI 视图本身无需测试。
@MainActor
@Observable
final class HUDViewModel {
    /// 文本区固定行数，超出后只显示末尾若干行。见 spec 第五节。
    static let maxLines = 4
    /// 每行大致容纳的字符数，用于折行估算。
    static let charsPerLine = 22
    /// 波形柱数。
    static let barCount = 24

    var phase: DictationSession.State = .idle
    var preview: PreviewText = .empty
    var elapsed: TimeInterval = 0
    /// 音量能量。**与 `preview` 分开**：文本来自流式转写的状态回调
    /// （1–2 秒一次），而波形要 20 fps 才不卡顿，由计时器直接从
    /// `SourceBackedAudioProcessor` 读取。
    var energy: [Float] = []
    /// 预览落后实时超过阈值后置位，文本停止更新但音量与时长照常。
    var previewDegraded = false

    var durationText: String { Self.formatDuration(elapsed) }
    var confirmedLines: [String] {
        Self.tailLines(preview.confirmed, maxLines: Self.maxLines, charsPerLine: Self.charsPerLine)
    }
    var unconfirmedText: String { preview.unconfirmed }
    var bars: [Float] { Self.waveformBars(from: energy, barCount: Self.barCount) }
    var statusText: String { Self.statusLabel(for: phase, previewDegraded: previewDegraded) }

    // MARK: - 纯函数

    nonisolated static func formatDuration(_ seconds: TimeInterval) -> String {
        let total = max(0, Int(seconds))
        return String(format: "%d:%02d", total / 60, total % 60)
    }

    /// 把文本折行后取末尾若干行。HUD 不可交互，因此不做滚动条。
    nonisolated static func tailLines(
        _ text: String,
        maxLines: Int,
        charsPerLine: Int
    ) -> [String] {
        guard !text.isEmpty, charsPerLine > 0, maxLines > 0 else { return [] }

        var lines: [String] = []
        var current = ""
        for character in text {
            current.append(character)
            if current.count == charsPerLine {
                lines.append(current)
                current = ""
            }
        }
        if !current.isEmpty { lines.append(current) }

        return lines.count > maxLines ? Array(lines.suffix(maxLines)) : lines
    }

    /// 把能量序列降采样成固定数量的波形柱，取末尾（最新）的部分。
    nonisolated static func waveformBars(from energy: [Float], barCount: Int) -> [Float] {
        guard barCount > 0 else { return [] }
        guard !energy.isEmpty else { return Array(repeating: 0, count: barCount) }

        let tail = energy.suffix(barCount)
        let clamped = tail.map { min(1, max(0, $0)) }
        // 不足时在前面补零，使波形从右侧生长。
        let padding = Array(repeating: Float(0), count: barCount - clamped.count)
        return padding + clamped
    }

    nonisolated static func statusLabel(
        for phase: DictationSession.State,
        previewDegraded: Bool
    ) -> String {
        let base: String = switch phase {
        case .idle: "就绪"
        case .listening: "正在聆听"
        case .transcribing: "正在转写"
        case .injecting: "正在输入"
        }
        if phase == .listening, previewDegraded {
            return base + "（预览已暂停）"
        }
        return base
    }
}
```

```swift
import AppKit
import SwiftUI

/// 承载 HUD 的无焦点浮动面板。
///
/// **不抢焦点是硬约束。** 用户在别的应用里说话，焦点必须始终留在那个
/// 输入框上，否则文字无处可注。因此：
/// - `.nonactivatingPanel` 样式，点击不激活本应用
/// - `canBecomeKey` / `canBecomeMain` 均为 false
/// - 视图里不放任何可点击控件（鼠标事件根本不会送达）
@MainActor
final class HUDPanel {
    /// 面板底边距屏幕底部的距离。
    static let bottomMargin: CGFloat = 120

    private var panel: NSPanel?
    private let model: HUDViewModel

    init(model: HUDViewModel) {
        self.model = model
    }

    /// 计算面板在给定屏幕上的原点。抽成静态纯函数以便单测。
    ///
    /// AppKit 坐标系原点在左下角，故 y 直接取边距。
    nonisolated static func originFor(screenFrame: CGRect, panelSize: CGSize) -> CGPoint {
        let x = screenFrame.origin.x + max(0, (screenFrame.width - panelSize.width) / 2)
        let y = screenFrame.origin.y + bottomMargin
        return CGPoint(x: x, y: y)
    }

    func show() {
        if panel == nil { panel = makePanel() }
        guard let panel else { return }

        reposition(panel)
        // orderFrontRegardless 而非 makeKeyAndOrderFront：
        // 后者会抢焦点，导致文字注入失败。
        panel.orderFrontRegardless()
        panel.alphaValue = 0
        NSAnimationContext.runAnimationGroup { context in
            context.duration = 0.15
            panel.animator().alphaValue = 1
        }
    }

    func hide() {
        guard let panel else { return }
        NSAnimationContext.runAnimationGroup { context in
            context.duration = 0.2
            panel.animator().alphaValue = 0
        } completionHandler: { [weak panel] in
            panel?.orderOut(nil)
        }
    }

    private func makePanel() -> NSPanel {
        let hosting = NSHostingController(rootView: HUDView(model: model))
        let panel = NSPanel(
            contentRect: .zero,
            styleMask: [.borderless, .nonactivatingPanel],
            backing: .buffered,
            defer: false
        )
        panel.contentViewController = hosting
        panel.isFloatingPanel = true
        panel.level = .floating
        panel.backgroundColor = .clear
        panel.isOpaque = false
        panel.hasShadow = true
        panel.hidesOnDeactivate = false
        // 在所有 Space 与全屏应用之上显示——用户可能在全屏编辑器里口述。
        panel.collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary, .stationary]
        panel.ignoresMouseEvents = true
        return panel
    }

    private func reposition(_ panel: NSPanel) {
        panel.layoutIfNeeded()
        let size = panel.contentViewController?.view.fittingSize ?? CGSize(width: 420, height: 160)
        let screen = NSScreen.main?.frame ?? CGRect(x: 0, y: 0, width: 1_440, height: 900)
        let origin = Self.originFor(screenFrame: screen, panelSize: size)
        panel.setFrame(CGRect(origin: origin, size: size), display: true)
    }
}
```

```swift
import Carbon.HIToolbox
import Foundation

/// 取消热键的注册能力。抽成协议以便测试注册时机。
@MainActor
protocol CancelHotkeyRegistering: AnyObject {
    func registerCancelKey(handler: @escaping () -> Void) throws
    func unregisterCancelKey()
}

/// 用 Carbon 注册 `Esc` 作为取消键。
@MainActor
final class EscHotkeyRegistrar: CancelHotkeyRegistering {
    private let registrar = HotkeyRegistrar()

    func registerCancelKey(handler: @escaping () -> Void) throws {
        // 无修饰键的 Esc。仅在录音期间注册，见 CancelHotkeyController。
        try registrar.register(keyCode: UInt32(kVK_Escape), modifiers: 0, handler: handler)
    }

    func unregisterCancelKey() {
        registrar.unregister()
    }
}

/// 按会话状态管理取消热键的注册与注销。
///
/// `Esc` 是高频键，长期占用会干扰其他应用——因此**只在录音期间注册**，
/// 一离开 `.listening` 立即注销，影响范围限于说话的那几秒。
@MainActor
final class CancelHotkeyController {
    var onCancel: (() -> Void)?

    private let registrar: CancelHotkeyRegistering
    private var isRegistered = false

    init(registrar: CancelHotkeyRegistering) {
        self.registrar = registrar
    }

    /// 会话状态变化时调用。
    func update(for state: DictationSession.State) throws {
        if state == .listening {
            guard !isRegistered else { return }
            do {
                try registrar.registerCancelKey { [weak self] in
                    self?.onCancel?()
                }
                isRegistered = true
            } catch {
                // Esc 注册失败不该阻断录音——⌥D 仍能正常结束会话。
                AppLogger.shared.log("取消热键注册失败，本次录音无法用 Esc 取消：\(error)")
                isRegistered = true   // 避免每次状态变化都重试并刷屏
```

## 风险与备选

### 风险 1：流式与全量共享解码器导致崩溃或乱码

已在 Task 4 与 Task 5 用「停止时等待推理循环退出」处理。若真机仍出现崩溃或输出错乱，说明 `stopStreamTranscription()` 之后仍有残留并发。

备选：为预览单独加载第二个 `WhisperKit` 实例（内存翻倍，turbo 从 1.5 GB 涨到 3 GB），彻底隔离。这是最后手段，实施前先向用户报告实测现象。

### 风险 2：预览跟不上说话速度

spec 第七节要求「落后实时超过 3 秒时降级」。本计划**未实现该降级逻辑**——`HUDViewModel.previewDegraded` 字段已预留但无人置位。

理由：降级阈值需要真实数据才能定得准，而 Task 11 的双模型实测正是取这组数据。若实测发现 `turbo` 下从不积压，该逻辑就是过度设计；若 `large-v3` 下频繁积压，再按实测数据实现。

**这是一个有意的缺口，不是遗漏。** Task 11 记录实测结果后决定是否补。

### 风险 3：`AudioStreamTranscriber` 的中文表现未知

WhisperKit 的流式实现主要面向英文调优，`requiredSegmentsForConfirmation: 2` 等参数对中文是否合适未经验证。若实测发现确认过慢（文本迟迟不转为「已确认」）或过快（确认后仍被改写），调整该参数并记录。

### 风险 4：全屏应用下 HUD 不可见

已设 `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary, .stationary]`。若在全屏编辑器中仍不可见，改为 `.screenSaver` 层级并重测——但那会盖住系统菜单，需权衡。
