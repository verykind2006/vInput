## 二、核心目标

**按住语音键说话，效果应与按 `⌥D` 完全一致。** 这是本里程碑的全部意义。

| 检查项 | 结果 |
|---|---|
| 按住语音键，HUD 出现 | ✅ |
| 说话时实时预览逐字显现 | ✅ |
| 音量波形随说话起伏 | ✅ |
| 松开后文字注入光标处 | ✅ |
| 目标应用的光标全程保持闪烁 | ✅ |
| **与 `⌥D` 的行为无差异** | ✅ |

**过程中发现并修复的阻塞问题：语音键同时是 HID 按键。**
RC003 的语音键不只走 BLE，按住期间 macOS 会把它当普通按键（keyCode 96 / F5）
持续投递给前台应用。输入框被自动重复的按键填满，随后注入的文字被淹没——
表现为「遥控器录音后没有文字」，而 `⌥D` 一切正常。`RemoteKeySuppressor`
用 CGEvent tap 在会话期间吞掉该键解决。键码来自真机按键日志，不是从终端
里的转义序列推断（最初按 `5~` 猜成 Page Up 是错的）。

## 五、保活（相对上游的额外验证）

上游文档记录「RC003 是否能因 `MIC_EXTEND` 录过 60 秒仍需真机验收」，状态挂在**「等待人工验收」**至今。本项目有硬件，首次真正确认。

| 检查项 | 结果 |
|---|---|
| 按住语音键持续说话**超过 60 秒**不中断 | ❌ 固件在 60 秒切断 |
| 实际能持续的最长时长 | **60.04 秒** |
| 达到上限时正常结束并转写，不丢弃已录内容 | ✅ 297 字完整注入 |

**结论：RC003 不支持 `MIC_EXTEND` 续期。上游那个「等待人工验收」的问题，
答案是否定的。**

证据（session 41，`vInput.log` 2026-08-14）：

```
20:36:09.380  遥控器语音键按下，开始录音
20:36:19.360  ATVV MIC_EXTEND request session=41
20:36:29.363  ATVV MIC_EXTEND request session=41
20:36:39.359  ATVV MIC_EXTEND request session=41
20:36:49.365  ATVV MIC_EXTEND request session=41
20:36:59.367  ATVV MIC_EXTEND request session=41
20:37:09.359  ATVV MIC_EXTEND request session=41
20:37:09.420  ATVV STREAM STOP session=41
20:37:14.530  注入成功 文本长度 297 字
```

六次续期报文全部成功写入，设备收到后忽略，仍在整 60 秒切断。

**这个结论此前拿不到，是因为保活代码从未真正运行过。**
`requestMicrophoneExtend()` 的 guard 里有 `microphoneOpened`，而该标志只在
主机主动开麦时置位；RC003 的实际用法是用户按遥控器实体键、**由设备发起**
会话，那条路径只置 `streaming`。于是续期每次都被自己的 guard 拦下，日志却
含糊地记成 `rejected`，看着像是设备拒绝。修复后才第一次真正发出报文。

**保活代码予以保留**：协议上是正确的，成本仅每分钟 6 次 BLE 写入，
换用其他 ATVV 遥控器时可能有效。

**不阻塞 M3 验收**：60 秒对遥控器的目标场景（写 prompt、发消息）足够，
且到点后行为是体面的——完整转写已录内容，不丢字。长文本来就走内置麦。

**即使保活无效也不阻塞 M3 验收** —— 60 秒对遥控器的目标场景（写 prompt、发消息）足够，长文本来就走内置麦。如实记录实测时长即可。

## 结论

- **M3 验收标准是否达成**（按住语音键说话，效果与 `⌥D` 一致）：**达成。**
  连续多次会话全部成功注入（6 / 13 / 29 / 38 / 49 / 297 字），HUD、实时预览、
  波形、光标保持均与 `⌥D` 无差异。

- **保活实测结论：RC003 不支持 `MIC_EXTEND`，60 秒为固件硬上限。**
  这回答了上游长期挂在「等待人工验收」的问题，答案是否定的。到点后行为体面：
  完整转写已录内容，不丢字。60 秒对遥控器的目标场景（写 prompt、发消息）足够。

- **发现并修复的问题：**
  1. **语音键同时是 HID 按键**（keyCode 96 / F5），按住期间持续投递给前台应用，
     淹没随后注入的文字。这是「遥控器录音后没有文字」的真正原因，一度被误判为
     注入失效。`RemoteKeySuppressor` 解决。
  2. **保活代码从未运行过**——guard 里的 `microphoneOpened` 只在主机主动开麦时
     置位，而 RC003 是设备发起会话。修复后才第一次真正发出续期报文，也才拿到
     上面那个结论。
  3. **模型缓存默认写入 `~/Documents`**（TCC 保护目录），LSUIElement 应用无处
     呈现授权弹窗，导致启动无限期阻塞。改到应用支持目录。

- **未验证项：** 取消功能整节（使用者明确决定不验），连接的断连/重连/蓝牙关闭
  文案，以及录音中途断连。均已在上文标注原因与补验方法。

- **对 M4 的影响：** 识别质量是当前最突出的短板。真机出现「小米**遥控器**」→
  「小米**耀空气**」这类同音词错误，纯声学解码无法自行纠正，需要语言模型在上层
  校正——这正是 M4 的内容。一个更便宜的先手是给 WhisperKit 传 initial prompt
  偏置领域词汇，成本近零但覆盖面窄得多。

## 已知的待决项

1. **`Package.swift` 仍用本地路径依赖** `vendor/WhisperKit`（M1 遗留，因当时网络丢包）。网络好转后应改回版本化远程依赖。
2. **模型路径解析仍是开发期布局**（M1 遗留），正式分发需改为应用支持目录。
3. **模型选择不持久化**（M1 遗留），重启回到偏好列表第一个。
4. **预览积压降级未实现**（M2 有意留的缺口），`HUDViewModel.previewDegraded` 字段已预留但无人置位。
5. **开发期签名导致授权反复失效**：`build-app.sh` 默认 ad-hoc 签名，指纹随
   二进制变化，每次构建都会作废辅助功能与输入监控授权。M3 期间这条摩擦一度
   让人把权限问题误判为功能故障。脚本已改为「有固定自签名身份则用之」，
   创建方法见 `docs/dev-signing.md`——**该证书尚未在本机创建**。
6. **本地化系统未移植**，`LocalizedMessage` 只有 key。已在 `RemoteConnectionState` 里做了 8 个已知 key 到中文的映射，上游若新增状态会走「连接异常」的兜底文案。
