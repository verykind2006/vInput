## 三、取消

| 检查项 | 结果 |
|---|---|
| 说到一半按遥控器**返回键**，会话取消 | |
| 没有任何文字被注入 | |
| 取消后再按语音键能正常开始 | |
| 先按返回键取消、再松开语音键，不会重复触发一次转写 | |

最后一项对应 `RemoteCoordinator` 里的状态过滤——用户按取消后才松手是很自然的动作顺序。

## 四、异常路径

| 检查项 | 结果 |
|---|---|
| 录音中途关闭遥控器，**已说的内容仍被转写注入** | |
| 极短按压（按一下就松）不弹错误 | |
| 未授予输入监控权限时，语音键仍可用（仅返回键失效） | |

第一项是「规则二·永不丢字」在蓝牙场景的体现：`DictationSession` 只在 `.listening` 期间响应音频源错误，进入转写阶段后到达的断连一律忽略——那时音频已完整拿到手，中止反而是在丢字。

## 五、保活（相对上游的额外验证）

上游文档记录「RC003 是否能因 `MIC_EXTEND` 录过 60 秒仍需真机验收」，状态挂在**「等待人工验收」**至今。本项目有硬件，首次真正确认。

| 检查项 | 结果 |
|---|---|
| 按住语音键持续说话**超过 60 秒**不中断 | |
| 实际能持续的最长时长 | |
| 达到 180 秒上限时正常结束并转写，不丢弃已录内容 | |

**即使保活无效也不阻塞 M3 验收** —— 60 秒对遥控器的目标场景（写 prompt、发消息）足够，长文本来就走内置麦。如实记录实测时长即可。

## 已知的待决项

1. **`Package.swift` 仍用本地路径依赖** `vendor/WhisperKit`（M1 遗留，因当时网络丢包）。网络好转后应改回版本化远程依赖。
2. **模型路径解析仍是开发期布局**（M1 遗留），正式分发需改为应用支持目录。
3. **模型选择不持久化**（M1 遗留），重启回到偏好列表第一个。
4. **预览积压降级未实现**（M2 有意留的缺口），`HUDViewModel.previewDegraded` 字段已预留但无人置位。
5. **本地化系统未移植**，`LocalizedMessage` 只有 key。已在 `RemoteConnectionState` 里做了 8 个已知 key 到中文的映射，上游若新增状态会走「连接异常」的兜底文案。
